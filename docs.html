Conventions

The tool reference publishes with the release. At launch, these rules will hold for every tool.

  • Project tools are named <module>_<verb>: the project, then the action.
  • Amounts are decimal strings in the asset's smallest unit, never floating-point numbers.
  • Every result names the asset address, symbol, chain ID and decimals.
  • Before signing, the add-on will simulate (test-run) the transaction sequence (eth_simulateV1) and show the resulting balance changes.
  • Errors come back as plain sentences that say what to fix.
  • A set of basic tools covers the common jobs across every project: look up a verified asset by name, symbol or address, read balances and dollar values, get a quote that compares two routes, preview, swap, read the wallet's history, and list its open positions.

Each group below lists what the agent will be able to do at launch, with a prompt you could try. USDG (US dollar stablecoin) appears in several of them.

Swap and Trade

8 projects

KyberSwap, Velora, Pons, pools.trade, Clanker, Hookr, TickerSpring, Uniswap liquidity

Example prompt

Swap 50 dollars of ETH to USDG with the best route, and show me the preview before anything is signed.

  • Compare routes from KyberSwap and Velora by net output, and refuse any swap that would pay out less than the quoted minimum.
  • Launch a coin on a Pons bonding curve (a formula that sets the cost as people buy and sell), buy and sell it, and graduate it to a liquidity pool.
  • Launch and trade coins through pools.trade and Clanker.
  • Create, cancel and claim limit orders through Hookr and TickerSpring.
  • Add, collect and remove liquidity positions with Uniswap liquidity.

Command line

The main commands, all run on your computer:

CommandWhat it does
oak initCreates the wallet. Run it in your own terminal only.
oak addressShows the agent's wallet address.
oak exportExports the private key. Run it in your own terminal only.
oak mcpStarts the MCP (AI tool connector) server that your agent connects to.
oak call <tool> <json>Calls one tool directly from the command line.
oak registerRegisters the agent's on-chain identity.
oak recipes add <package-or-path>Imports a project recipe. Also: remove and list.
oak config set <key> <value>Sets an endpoint or an address.

Project recipes

A project team can publish an opt-in recipe that adds its own read and action definitions. A recipe is data only, so no third-party code runs. Each is limited to 64 KiB per file, 4 MiB per archive and 100 entries, and labelled as-is, not reviewed by Oak. You import one yourself with oak recipes add.

For AI agents

Works with: Claude Code Codex Gemini Cursor Grok and any other MCP client that can run a tool server on your computer.

An operating guide for agents, AGENTS.md, and a plain-text summary, llms.txt, ship with the kit. Their custody rules are short:

  • Never run oak init or oak export inside an agent tool call. The human owner runs both in their own terminal.
  • Never ask the user for a private key, seed phrase or passphrase. Oak will reject any tool argument that contains one.
  • All signing happens locally in the add-on.
  • Always read the preview before signing.
